# API tests and fixtures

1. Prefer small inline responses with `jsonResponse()` for behavior tests. For recorded **Avanza** responses, use `avanza <command> --fixture --output <new temporary path>` after `pnpm build`. **Nordnet** has no CLI: write a throwaway script in the private temporary directory from step 2 that creates a `NordnetClient` with a `fetch` wrapper recording each request and response in the same `request` / `response` shape, and never save that script in the repository. Nordnet logins are BankID only, so the user must scan the QR code themselves. Only authenticated commands need a stored session; never put credentials into source, shell history, or tests. `--fixture` is **raw**: `--json` redactions do not apply to it. Do not direct `--output` or `>` into a tracked fixture path.
2. Create the capture outside the repository, in a private temporary directory (e.g. `capture_dir=$(mktemp -d)` then `node packages/avanza-cli/bin/run.js auth session --fixture --output "$capture_dir/raw.json"`). The output path must not exist yet. Do not print raw captures in logs or paste them into issues. Delete the temporary directory when done, including on failure.
3. Before copying **any** data under `packages/avanza/src/**/fixtures/` or `packages/nordnet/src/**/fixtures/`, inspect both `request` and `response` and anonymize **personal data only**: credentials, cookies, tokens, customer/account IDs, personal text, and private identifiers in paths or query strings. Stock names, orderbook/company IDs, prices, volumes, and other public market data should stay as captured, unless the value comes from or reveals a personal account or customer-specific context (for example, holdings, watchlists, or account-specific stock flags). Preserve the JSON shape, states/enums, and values needed by the SDK parser. Use stable synthetic replacements with a valid format where parsing requires one. Keep the `request` / `response` shape in each package's `src/test-utils/http.ts`. Nordnet session cookies, bearer tokens, `customerId`, `accid`, `accno`, and `account_id` values are personal.
4. Inspect the fixture and `git diff` for personal data **before** staging or committing. The raw capture must stay outside the repository. If the provenance of a value is unclear and it might be personal, anonymize it or do not add the fixture; do not anonymize public stock data merely because it contains an identifier.
5. Write `src/**/*.test.ts` tests using an injected mocked `fetch` and fake hosts: `baseUrl: 'https://example.test'` for Avanza, and the `WEB` / `API` hosts from Nordnet's `test-utils/http.ts` (`webBaseUrl` / `apiBaseUrl`). Never call the live API in tests. Reuse `loadHttpFixture()` / `httpFixtureResponse()` and assert both the parsed result and the outgoing method/path/body when relevant. The fixture response helper does not assert the fixture's request metadata for you.
6. Run the focused test and `pnpm check`. Do not create or update a Changeset unless explicitly requested.
